# 积分与荣誉使用说明

第一版规则已按确认方案实现。积分只用于社区等级与荣誉，不提供现金、兑换、消费权益、签到或邀请任务。

## 页面入口

| 页面 | 地址 | 功能 |
| --- | --- | --- |
| 我的贡献 | `/me?tab=honors` | 等级进度、本周分类积分、流水、贡献资格、勋章墙、规则 |
| 社区贡献榜 | `/honors` | 综合、案例、资源、答疑四榜，周次与历史版本选择 |
| 作者主页 | `/author/:id` | 累计有效积分、等级、六枚勋章及获得详情 |
| 管理后台 | `/admin?section=honors` | 贡献确认、规则、积分追溯、人工勋章 |

首页侧栏展示本周成员贡献榜；原内容点赞/下载人气榜仍在 `/rankings`。帖子、资源作者与回复作者显示等级及已获得勋章。空榜与新账号不生成示例成绩。

## 发分与资格

| 贡献 | 条件 | 分值及上限 |
| --- | --- | --- |
| 案例 | `experience` 原创、实用，实际问题、做法与结果完整，审核通过并确认资格 | 每次 20 分，每人每周最多 3 次 |
| 资源 | `project` 或 `skill`，说明完整，链接或文件可用，审核通过并确认资格 | 每次 20 分，每人每周最多 3 次 |
| 答疑 | 提问中的回答通过内容审核，由提问者本人采纳，且非自问自答 | 每次 20 分，每人每周最多 3 次 |

三类独立限额，合计每周最多 180 分。独立提示词、一般发帖、签到、浏览和点赞不加分。版主代采纳不发分，提问者本人确认后才满足采纳条件。

在原审核队列的人工通过窗口，可勾选“同时确认贡献资格”；未勾选时照常发布，在“积分与荣誉 → 贡献确认”中另行确认。普通自动审核通过仅代表内容可发布，案例及资源仍需人工确认实用性、原创性或完整性。

账号免审仍然即时发布；免审案例、资源和被采纳的免审回答需单独人工确认贡献资格，避免将发布权限等同于荣誉资格。个人密钥投稿走同一流程。

审核人员须实际检查外部链接、原创性和使用说明。服务端检查关联文件状态、磁盘可读性、大小及内容摘要，并识别已记录贡献的相同正文、相同资源链接与完整文件集合；图片回答使用文件内容摘要，重新上传同一图片不能通过更换附件 ID 重复计分。独立项目仅共用一个说明文件不会因此被判重复。这些检查不是语义查重，也不是外部链接持续健康监测。

## 周期、撤回与恢复

- 北京时间周一 00:00（含）至下周一 00:00（不含），数据库保存真实时间戳与所属周。
- 第一次满足全部条件的时间决定贡献所属周；先投稿、后审核的贡献按资格生效周计算。
- 每类同周最早的三份有效贡献计分，之后的有效贡献保留但记 0 分，不滚入下周。
- 删除、下架、撤销采纳、撤回资格、已审核版本变化或文件被隔离，会重新计算积分与勋章。已有待审修订不会提前替换仍公开的旧版本。
- 失效贡献撤回 20 分，并在原周按首次有效时间补位；恢复仍归原周，重新按顺序分配，不能凭恢复取得第二份积分。
- 原正流水保留，撤回追加负流水并关联原发分记录。来源无权访问或已删除时不暴露标题与链接。
- 现有内容与评论在迁移时标记为不参与；本版不为历史内容自动补分。启用时间可在规则页查看。

## 等级与榜单

已确认等级：共创新人 0、实践新秀 60、分享达人 180、共创骨干 420、共创先锋 900、共创领航者 1800 分。累计有效积分不随换周清零；撤分后等级与下一等级进度同步变化。

榜单只计算该周有效贡献积分，不使用点赞量排序。同分并列，名次示例为 1、1、3；同分展示顺序不代表更高排名。0 分成员不列入榜单。

当前周实时读取；周结束后保存快照。服务启动与每分钟定时任务补齐已结束周，停机不丢历史周。撤回或补位改变历史成绩时新增更正版本，旧版继续保留并可查看。周期选择使用北京时间，计时依赖服务主机时钟正确。

## 六枚勋章

| 勋章 | 方式 | 获得条件 |
| --- | --- | --- |
| 首次分享案例 | 自动 | 首篇有效原创案例 |
| 首次分享资源 | 自动 | 首份有效项目或技能资源 |
| 首次解答被采纳 | 自动 | 首条有效被采纳回答 |
| 全能共创者 | 自动 | 三类各至少一份有效贡献 |
| 持续共创者 | 自动 | 历史任意连续四个自然周都有有效贡献 |
| 优质贡献者 | 人工 | 管理员评选，必须填写公开授予理由 |

超周积分上限的有效贡献仍用于勋章资格。持续共创者获得后，后续断周不撤销；如果原四周依据失效，则重新校验是否仍有其他连续四周。其他自动勋章同样可使用替代的有效贡献保持资格，不凭一次失效直接撤销全部荣誉。

人工勋章可关联本人有效贡献作为评选依据；依据失效后标记“待复核”，管理员需填写理由保留或撤销。保留操作记录原依据与新理由，转为本次人工复核决定。授予、撤销、复核均有操作日志。点击勋章查看条件、获得时间、自动/人工标识和人工理由。

六枚图像由内置 image_gen 独立生成，以品牌红、暖白和金色为主。原图与提示词位于 `docs/assets/badges/`；运行时使用 `public/brand/badges/` 的 256px 透明 WebP，每枚约 13–18 KB。

## 数据与维护

迁移 `013_community_honors.sql` 新增贡献资格、签名、积分流水、周限额桶、历史榜单版本及条目、勋章定义与授予记录；扩展附件内容摘要、提问采纳者及时间、历史资格开关。现有内容与账号关系保留。

贡献以内容 ID 或回答 ID 唯一识别，流水以贡献状态变化序号作为幂等键。所有发分、撤回、补位、勋章和快照变化处于数据库事务中。先锁来源，再取得社区荣誉事务锁，串行处理资格与跨类别奖励；当前实现适用于内部社区，未进行大规模压力测试。

管理员不能任意增加现金式余额：异常处理通过有原因的资格撤回，保留审计链。版主只能处理已授权的来源，人工授勋与人工复核仅超级管理员可操作。成员只能查看自己的积分流水；公开主页只展示荣誉汇总。

主要接口在 `server/honors-routes.ts`；计算与补位在 `server/honors-engine.ts`；等级和北京时间周计算在 `server/honors-policy.ts`。新增接口沿用登录、CSRF、角色及范围鉴权。

测试包括发分幂等、每类周上限、跨周与跨年、撤回与恢复、原周补位、并列榜和历史更正、六类勋章、权限、重复来源、免审以及浏览器实际审核和授勋流程。详细执行结果见 `docs/VERIFICATION.md`。生产 PostgreSQL 并发压力与 Docker 实际运行尚未在本机验证。
