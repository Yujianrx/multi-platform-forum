# 删除功能与内容榜单设计

需求来自用户在服务器部署对话中的明确实施指令，已授权开发、验证与交付；不执行任何线上真实删除。

现状：内容软删除接口已存在，草稿箱没有删除入口且包含已发布文章的新草稿；账号只有停用；旧 `/rankings` 仅有点赞与下载，论坛另有按用户去重的阅读状态。贡献榜独立。

选择沿用现有软删除与事务体系。物理级联删除账号会破坏文章、评论、审核、邀请及积分外键，单纯停用又不满足删除操作，因此新增不可重新启用的删除标记，保留作者 ID 和历史关联，显示“已删除成员”，保留原登录名避免身份冒用。删除撤销所有会话、密钥、重置凭证和管理范围，清除头像与简介，从成员管理列表移除。管理员操作且不能删除本人，保留有效管理员；原因与操作者进审计，原有未删除用户不受影响。

草稿箱增加逐项删除和确认：未发布内容软删除；已发布文章的当前未提交草稿只标记丢弃并退回公开修订，公开文章及积分不受影响。已下架内容可从草稿箱删除。附带当前修订 ID，权限和状态在事务锁后再次检查，防止旧页面误删刚提交或发布的内容。

浏览榜新增真实事件表：登录用户实际打开已发布且有权访问的内容时记录，排除作者，同人同内容每个北京时间日期计一次。论坛阅读端点同时记事件，资源详情独立记事件。近 7 天、近 30 天与累计支持，现存 forum_visits 只迁移真实已知的最近访问一次，不推测更早访问；不导入示例数据。保留点赞榜、下载榜、贡献榜，并在首页提供点赞/浏览快捷入口。

结构使用新增 014 迁移，不改动线上已应用的 001–013。维护文档固化批量审核、通过免原因、附件同事务放行、19 条规则、可选贡献确认、账号免审与线上数据保留约束。构建、权限/状态/关联一致性测试及完整既有回归后交付源码与迁移清单，实际部署由原服务器流程处理。
