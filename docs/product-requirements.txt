请作为全栈开发工程师和产品设计师，在当前项目中开发一个可实际使用的公司内部 AI 分享社区。

请先检查项目目录和已有说明，沿用合理的现有架构。空项目则选择便于维护、可自行部署的成熟技术方案。完成需求拆解后分阶段实现、运行和验证，持续推进到可本地使用并具备部署条件。

下面的产品方向已经确定。常规实现细节自行作出合理选择并记录；只有缺少必要凭证、存在重大需求冲突或必须了解服务器环境时才询问我。

一、产品定位与边界

平台暂名“AI 共创社区”，名称、Logo 和简介可在后台修改。

目标是让公司员工分享 AI 经验、展示开发项目、发布 Skill 技能包和提示词，其他员工可以浏览、搜索、点赞、收藏、评论、下载和复用。

已确定：
- 仅供公司内部使用。
- 邀请码注册，账号密码登录。
- 发布者可以选择全公司可见，或指定一个／多个部门可见。
- 系统自动审核，通过后立即发布。
- 首页采用“分享社区＋资源广场”形式。
- 视觉采用活跃、友好、有品质的社区风格。
- 电脑端为主，适配手机。
- 计划部署到现有美国服务器；具体系统和配置尚未提供。

首版不接入企业微信登录，不增加支付、商城、积分、私信、在线执行技能包等功能。

二、视觉与交互

采用浅暖色背景、橙色或珊瑚色主色、少量青绿色辅助色。使用舒适留白、清晰层级、适度圆角和轻微阴影。

突出作者头像、内容封面、分类标签、互动数据，让平台有真实的社区氛围。装饰和动效应服务阅读，保持中文长标题、正文、代码块的可读性。

建立统一的颜色、字号、间距、卡片、按钮、表单和反馈样式。

必须设计并实现：
- 加载、空数据、错误、无权限状态。
- 表单校验、保存状态、操作成功和失败反馈。
- 上传进度、审核状态及退回原因。
- 键盘操作、明显焦点、基本对比度要求。
- 手机端导航、卡片、发布表单和排行榜布局。

三、账号、邀请码与部门

注册字段：
姓名、账号、密码、确认密码、邀请码；部门由邀请码或管理员分配。

账号密码登录，支持退出登录、修改密码。默认使用管理员发起的一次性密码重置流程，用户重置后强制设置新密码。

邀请码：
- 由管理员生成。
- 可设置有效期、使用次数、默认部门。
- 支持撤销、查看使用记录。
- 注册与邀请码名额扣减使用事务处理。
- 防止并发注册超额使用同一个邀请码。
- 普通注册不得获得管理员或版主角色。

部门：
- 管理员维护部门和成员归属。
- 普通成员不能通过修改个人资料自行取得其他部门权限。
- 管理员调整部门后，新的访问权限应及时生效。

账号停用后立即阻止登录并使已有会话失效，保留其历史内容和作者归属，内容可由管理员处理。

管理员初始账号通过安全初始化流程创建，不在源码中写入固定生产密码。

四、角色与访问权限

默认三级角色：
1. 普通成员：管理自己的内容，访问授权内容并互动。
2. 版主：在管理员指定的部门／分类范围内处理内容、评论、举报及人工复核。
3. 超级管理员：管理全站成员、权限、内容、审核、配置和运营数据。

内容可见范围：
- 全公司：所有有效登录成员可见。
- 指定部门：属于任一指定部门的成员可见。
- 作者可查看自己的草稿、待审核和被退回内容。
- 管理人员根据其明确授权范围执行管理操作。

权限必须在服务端统一校验，覆盖：
列表、详情、搜索、首页轮播、推荐、排行榜、个人主页、评论、通知、历史版本、附件和图片访问。

无权限内容不能通过标题、摘要、封面、数量统计或缓存泄露。直接请求接口、资源地址或修改内容 ID 不能绕过权限。

内容收窄可见范围、用户更换部门、账号停用后，缓存和相关展示应随之失效。

五、发布类型、分类与标签

“内容类型”与“分类”“标签”分别建模。

四种内容类型：

1. AI 经验分享
标题、摘要、封面、正文、分类、标签、可见范围。
支持图文、Markdown、代码块、链接和示例。

2. 开发项目
公共字段，以及：
项目说明、解决的问题、截图、技术栈、使用方法、参与成员、演示地址、代码仓库地址、可选下载附件、版本和更新日志。

3. Skill 技能包
公共字段，以及：
适用工具、技能用途、运行环境或依赖、安装步骤、使用示例、版本号、更新日志、技能包附件。
工具名称可维护，允许自定义，不限制为某一家产品。

4. 提示词
公共字段，以及：
提示词正文、适用模型或工具、应用场景、输入说明、使用示例和效果示例。
支持一键复制，并反馈复制结果。

管理员维护分类与标签。
可预置办公提效、研发技术、数据分析、设计创作、业务应用等示例分类。

发布流程：
选择类型 → 填写内容 → 上传素材 → 设置分类与可见范围 → 预览 → 提交自动审核 → 发布。

支持草稿、自动保存、编辑、下架、删除确认。
项目和技能包支持新增版本，保留历史版本和更新说明；更新版本不丢失内容原有的点赞、评论及收藏。

六、自动内容审核

正常内容自动审核通过后立即发布，无需管理员逐条审批。

审核覆盖：
标题、摘要、正文、提示词、评论、封面、图片、附件说明，以及支持解析的附件内容。

审核规则覆盖色情、违规暴力、涉恐极端及公司明确禁止的违法违规内容。用户提出的“反动”等类别，应由管理员配置为明确、可解释的审核规则，不能只凭一个模糊标签或单个关键词判定。

采用规则检查与可替换的内容审核服务结合的设计：
- 明确通过：自动发布。
- 明确违规：拒绝发布，给作者展示可理解的原因。
- 疑似违规或无法可靠判断：等待人工复核。
- 审核服务异常：保持待审核并支持重试。
- 修改正文、图片、附件或提示词后重新审核。
- 审核结果必须绑定具体内容修订，避免旧审核结果放行新内容。
- 已发布内容提交修改时，保留此前通过审核的版本，直到新版本通过；主动收窄可见范围应立即生效。

后台应支持：
审核队列、命中类别、判定原因、审核记录、人工复核、规则配置、供应商连接状态和失败重试。

审核供应商尚未指定：
- 设计清晰的供应商适配接口。
- 集成前查阅所选服务官方文档，不虚构接口和识别能力。
- 明确哪些审核类别、文件格式已覆盖，哪些需要人工复核。
- 密钥仅保存在服务端环境变量或安全配置中。
- 未配置真实审核服务时，生产内容保持待复核。
- 测试模拟器只能用于开发和测试，必须与生产配置隔离。
- 缺少供应商凭证时先完成其他开发，准确列出待配置事项。

附件检查独立于文字审核：
- 校验实际文件类型和大小。
- 对支持的文本、图片及压缩包进行受限解析。
- 防止路径穿越、解压炸弹和恶意文件。
- 不执行用户上传的代码、脚本或技能包。
- 加密压缩包、无法解析或扫描失败的文件进入待复核，不能自动视为安全。
- 明确区分内容审核与恶意文件扫描，两者不能互相替代。

七、首页与内容发现

顶部导航：
首页、经验分享、开发项目、技能包、提示词、全站搜索、发布入口、消息、个人中心。

首页包括：
1. 轮播推荐。
2. 分类快捷入口。
3. 精选内容。
4. 最新分享。
5. 推荐项目与技能包。
6. 点赞榜、下载榜。

轮播后台可配置：
图片、标题、说明、目标内容或链接、顺序、启用状态、展示起止时间。
支持自动播放、手动切换和暂停；只展示当前用户有权访问的内容。

内容卡片展示：
类型、封面、标题、摘要、作者、分类标签、发布时间及适用的互动数据。
没有附件的内容不显示无意义的下载按钮。

分类页支持：
内容类型、分类、标签筛选，以及最新、点赞量、下载量排序；支持分页。

搜索至少支持中文关键词匹配标题、摘要、正文和标签，可结合类型、分类筛选。搜索结果在服务端按权限过滤。

八、排行榜与统计规则

提供点赞榜和下载榜：
- 周榜：近 7 天。
- 月榜：近 30 天。
- 总榜：累计数据。
- 首页可切换榜单，并支持查看完整榜单。
- 排名只包含当前用户有权查看的已发布内容。

统计规则要明确并写入说明：
- 同一用户对同一内容只能有一个有效点赞，可取消。
- 重复点赞、取消再点赞不能用于反复刷榜。
- 周榜、月榜按事件时间计算，不能直接使用累计总数。
- 站内下载以通过权限校验且成功提供文件的有效请求统计，不声称等同于用户实际保存完成。
- 榜单默认对同一用户、同一内容的下载按每天最多一次去重。
- 失败请求、无权限请求不计数，作者自己的下载不计入排行。
- 历史版本下载可汇总到所属内容，同时保留版本级明细。
- 外部资源链接只统计跳转次数，不冒充站内下载完成量。
- 禁用、下架、删除内容及时退出推荐和榜单。

九、互动、详情页与个人中心

互动：
点赞／取消、收藏／取消、评论、回复、举报。
评论与回复同样经过审核并继承父内容访问权限。

详情页根据内容类型展示完整信息、作者、互动入口、附件、版本记录和评论。项目演示和仓库链接清晰标注为外部链接。

通知：
评论回复、审核结果、内容下架及管理员通知。
支持已读／未读，接收人与内容查看范围需要校验；无权限或失效内容不能通过通知泄露。

个人中心：
我的发布、我的草稿、待审核／被退回内容、我的收藏、下载记录、消息、资料与密码设置。

作者主页只展示访问者有权查看的内容。

十、附件与存储

支持封面、正文图片、项目附件和 Skill 压缩包上传。

默认限制：
- 单张图片 10MB。
- 单个资源包 100MB。
- 后台可调整允许类型、大小和用户存储额度。

提供上传进度、失败重试、替换和删除操作。

初期可使用服务器持久化磁盘，存储层预留兼容 S3 的对象存储适配。

文件保存在受保护存储中，不直接暴露公共静态目录。每次下载均校验当前用户权限，文件地址不可作为永久绕过鉴权的入口。

展示原始文件名、大小、版本和更新时间；服务器存储名称使用安全唯一标识。下载记录写入真实数据库。

十一、管理后台

至少包含：
- 概览：用户、发布内容、互动、下载和待复核数量。
- 用户管理：部门、角色、停用、密码重置。
- 部门及邀请码管理。
- 内容管理：筛选、查看、精选、置顶、下架。
- 分类与标签管理。
- 轮播图管理。
- 评论、举报和审核管理。
- 附件与存储管理。
- 网站名称、Logo、简介和基础配置。
- 审核服务配置与状态。
- 操作日志。

管理员的账号权限调整、审核、下架、邀请码生成、关键配置修改均记录操作者、时间、对象和操作结果。日志不记录密码、密钥或完整登录令牌。

十二、技术实现与交付

优先采用易维护的模块化单体架构，不无故增加微服务。

已有项目沿用现有技术栈。
空项目可优先考虑 TypeScript、React、成熟服务端框架和 PostgreSQL；依据环境选择稳定兼容版本，说明选择理由。

要求：
- 数据真实持久化。
- 正确的密码哈希、安全会话、参数校验、登录和注册限流。
- 防止越权、SQL 注入、富文本 XSS 和跨站请求伪造。
- 审核任务可持久化、可重试、可恢复，避免仅依赖进程内任务。
- 用户上传内容只作为待处理数据，不能作为审核模型或后台任务的执行指令。
- 私有内容的服务端缓存、图片优化缓存和页面预渲染必须遵守权限边界。
- 数据库具备迁移、必要索引、唯一约束和事务。
- 列表分页，图片适当压缩与懒加载。
- 提供开发环境示例数据，覆盖四种内容类型和不同部门；生产初始化不混入虚构互动数据。
- 依赖版本锁定，环境变量提供模板但不包含真实密钥。

按实际实体设计数据结构，至少覆盖：
用户、部门、角色与授权、邀请码与使用记录、内容与修订、分类、标签、可见部门、资源版本、附件、点赞、收藏、评论、下载事件、通知、轮播、审核任务、举报、系统配置和操作日志。

交付：
完整源码、数据库迁移、开发示例数据、环境变量模板、启动说明、管理员初始化说明、Docker 部署配置、HTTPS 反向代理示例、备份与恢复说明、审核服务接入说明。

美国服务器的操作系统和资源尚未确认；可先按常见 Linux 容器环境准备部署方案，明确环境假设。没有实际连接或部署时，不得声称已经上线。

十三、实施顺序与验收

建议按以下顺序实施，每阶段完成后进行对应验证并记录状态：
1. 项目基础、设计系统、数据库、注册登录。
2. 邀请码、部门、角色与访问权限。
3. 四种内容发布、附件、版本与审核。
4. 首页、轮播、分类、搜索和排行榜。
5. 互动、通知、个人中心、管理后台。
6. 集成测试、桌面与手机视觉检查、部署文档。

重点验收：
- 无邀请码、失效邀请码、次数耗尽的邀请码不能注册。
- 邀请码最后一个名额在并发注册时不会被超额使用。
- 普通员工不能提升自身角色或擅自切换部门。
- 指定部门内容不会出现在其他部门的搜索、推荐、排行榜、通知或附件访问中。
- 账号停用后已有登录态失效。
- 四种类型均能完成创建、保存、审核、发布、编辑和下架。
- 自动审核通过、拒绝、疑似违规、超时、重试场景状态正确。
- 未配置审核服务时生产环境不自动放行。
- 修改内容不会错误沿用旧版本审核结果。
- 点赞、取消、收藏和评论刷新后仍保持正确状态。
- 下载鉴权、去重统计和外链跳转统计符合约定。
- 版本更新保留原有评论和互动关系。
- 管理后台配置能真实改变前台行为。
- 服务重启后用户、内容、文件和审核任务仍然存在。
- 桌面和手机主要页面无明显溢出、遮挡或不可操作问题。
- 实际运行构建、关键自动化测试和端到端流程，记录执行结果；未运行的检查明确说明。

最终报告提供：
已完成功能、本地访问与启动方式、实际测试结果、部署步骤、仍需我填写的配置和真实外部依赖限制。

现在开始检查当前项目，给出简明实施计划，然后按阶段推进开发和验证。
